# Issue 122 verification: AI workbench accessibility, responsive layout and operator recovery

Campaign: #118. Suite: #122. Tested on `main` @ `a2baddb` (includes #187-#190), local Docker stack, synthetic data only. Browsers: Chrome 155.0.8059.39 and Firefox 157.0.1 (both headless, fresh profiles, driven by real input events through the DevTools Protocol and WebDriver BiDi), plus the Claude in-app browser for the earlier spot checks. Live OpenAI (`gpt-6-luna`) produced the recommendation and draft content of UX-01 to UX-06 (partly), UX-08 to UX-11; the fault-injection stub (labelled FI) produced long/malicious AI text and provider failures (UX-06b, UX-07). Screenshots are in `issue-122-evidence/screenshots/`.

**Verdict for suite #122: NOT clean.** Six defects were filed (#191-#197 below; #191 and #192 are Medium). UX-07, UX-08, UX-09 and UX-10 pass, the keyboard journey passes, and the measured contrast and target sizes pass.

## Limitations and notes

- No real screen reader (UX-04), no Safari/WebKit, no physical device or touch input; mobile layouts were emulated by viewport and device-pixel-ratio overrides in Chrome and a viewport override in Firefox. The Firefox pass covers the critical journey and the layout matrix, not every case.
- Contrast and target size are computed from CSS (text over solid backgrounds; gradients and images are skipped), not a substitute for a visual review of every state; I reviewed the screenshots of the main states by eye.
- Harness incidents found and fixed during the run: DOM nodes returned by value are empty, a tab that is not in front can stall screenshots, and CDP `Fetch` interception hung screenshots (replaced by a `window.fetch` wrapper). The Firefox run was repeated after a stale session.
- Provider usage in this suite: roughly 50 live calls (recommendations and drafts across the journeys); check the dashboard for the exact figure.

## Checklist for a manual screen-reader pass (UX-04)

With NVDA or Orca on Firefox or Chrome: (1) log in and confirm the page title, language and the "Seguimientos" heading are announced; (2) move through the queue by heading and by landmark; (3) select a card (name, status and due text are read as one button); (4) press "Obtener recomendación" and confirm "Consultando al asistente…" then "Recomendación lista" are announced once, and where the cursor lands afterwards (#197); (5) press "Generar borrador" and confirm "Borrador listo para revisar" and the editor label "Borrador del mensaje (editable)"; (6) type past 1000 code points and confirm the counter is announced or discoverable; (7) read the evidence list (#194) and the warnings; (8) open Posponer and Descartar and confirm the dialog name, the focus trap and the focus return; (9) trigger an error (stop the provider) and confirm the alert text.

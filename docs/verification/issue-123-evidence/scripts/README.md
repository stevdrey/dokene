# Suite #123 scripts

Run from the root of a QA worktree with the stack up. `base.sh` sources the suite #121 environment helper (`../../issue-121-evidence/scripts/env121.sh`, which logs in as the seeded users) and uses `/home/stevdrey/qa123/` as the working folder.

- Provider faults use the suite #121 stub (`../../issue-121-evidence/scripts/Stub.java`, extended in this suite with `STATUS:COUNT:header=value` failures, a refusal output and a success-only delay `delay-ok.ms`). **Every provider response in `res0234`, `res04b`, `res05`, `res06`, `res07`, `res10` is injected**; the genuine OpenAI responses are the live baseline, RES-01 cases 4b, 6 (HTTP 401) and 7 (HTTP 404), the live recoveries inside `res07` and `res11`.
- Backend configuration per case is applied with a compose override file (environment only) and removed afterwards; the repository `.env` and compose files are not modified. Since issue 328 `res01.sh` keeps its override in a private directory from `scripts/lib/private-temp.sh` (mode 700, file mode 600, removed on any exit including an interrupt) and never writes the provider key into it: cases 4b and 7 leave the key out, so the backend keeps the one `compose.yaml` reads from `.env`. Before that change the override held the key and was removed only when the script reached its end.
- Since issue 329 every stub or offline case goes through `scripts/lib/provider-test-double.sh`: the override always sets the synthetic key, a destination that is not a loopback URL is refused before the backend is recreated, and `provider_test_assert_backend` stops the backend before the first request when it does not hold a loopback base URL with the synthetic key. The blackholed-address case of `res04b.sh` (`10.255.255.1`) is therefore replaced by a check that such a destination is refused; the OpenAI endpoint policy (issue 322) rejects that base URL at startup anyway. The outputs in `../outputs.txt` are from the original run, before this change. The check compares the backend with its baseline (the compose file's backend environment and secret mounts, the image's own variables, entrypoint, command and working directory); a script whose override adds other names declares them in `PROVIDER_TEST_EXTRA_NAMES`, as `res10.sh` does for the metrics exposure.
- `res10.sh` needs the disposable override `MANAGEMENT_ENDPOINTS_WEB_EXPOSURE_INCLUDE=metrics` and `MANAGEMENT_ENDPOINT_METRICS_ACCESS=read-only`; the default configuration exposes no metrics endpoint.
- `res07.mjs`, `res08ui.mjs`, `res11.mjs` use the suite #122 Chrome harness (`../../issue-122-evidence/scripts/cdp.mjs`); `res08ui.mjs` injects a lost response by wrapping `window.fetch` (the real request is sent, then the promise rejects).
- `res0234.sh` was rerun after two harness fixes (stub handler threads outlive a client timeout, so a settle wait and a success-only delay were added); `res06.sh` after its expectation was aligned with the documented HTTP 409 stale contract; `res08.sh` after the manual-completion expectation was aligned with ADR 0013. The outputs here are from the final runs.
